# Intent

Flashcard is the Quizlet-style drilling mode: flip a card to reveal the answer, then sort it into Know It or Still Learning. Pile membership persists per deck so a returning student resumes where they left off, and the flow lets them re-drill just what they haven't learned yet. It exists to support spaced, self-graded memorization for front/back decks that have no single "correct" multiple-choice answer.

# Requirements

- R1 [verify: ui] A card shows `front` on the front face and `back` on the back face, both KaTeX-rendered, with a 3D flip animation between them. Clicking the card (or space/Enter) toggles the flip. [caution: flipping must be disabled while a round is complete or while a sort animation is in progress, so stray clicks don't flip a card that's leaving.]
- R2 [verify: ui] Know It and Still Learning controls sort the current card and advance to the next. Know It plays a slide-out animation; Still Learning plays a brief shake. [caution: sorting is debounced for the animation window (~350ms) — ignore additional sort clicks until the animation completes and the next card renders, or cards get skipped.]
- R3 [verify: unit] [caution: piles are keyed by question `id`, NEVER array index — this is what lets progress survive question reordering across deck edits. Storing indices silently corrupts a returning student's progress.] Sorting Know It adds the card's `id` to the `known` pile (and removes it from `learning`); Still Learning adds it to `learning` (and removes it from `known`). Both also record the id in the current round's known/learning sets.
- R4 [verify: unit] Pile state is persisted to Storage (`getFlashState`/`setFlashState` by deck title) on every sort, so it survives a full page reload.
- R5 [verify: unit] [caution: sortCard is deliberately the ONLY entry point that decides pile assignment, isolated so a future spaced-repetition scheduler can replace just it. Keep sorting logic out of the render/advance code.] The advance step only reads the current position (`order`/`currentIdx` in linear mode, the head of `queue` in mastery mode); it does not itself decide pile membership. `sortCard` dispatches to a per-mode body (`sortCardLinear` / `sortCardMastery`), which differ only in how they advance — callers still have exactly one method to invoke and the scheduler seam stays one edit wide.
- R6 [verify: ui] A "Drill Still Learning only" toggle restarts the session with a deck of cards NOT in the `known` pile. [caution: "Still Learning" for drilling = every card not yet marked Know It, which INCLUDES cards never seen before, not only cards explicitly marked Still Learning.]
- R7 [verify: ui] A "Random order" toggle restarts the session with the deck shuffled; unchecked restores natural order. Toggling either the drill or random toggle restarts the session from the top with the new options. The shuffle is `shuffleArray` from `src/lib/shuffle.ts` (Fisher-Yates), applied at one site that both linear `order` and mastery-mode `queue` derive from. [caution: do not shuffle with a `sort(() => Math.random() - 0.5)` comparator — it looks random but is measurably biased toward leaving cards near their original position, which is exactly what a student turning this toggle on is trying to escape. And don't add a second shuffle for the mastery queue: it is carved from the already-shuffled ids.]
- R8 [verify: ui] A progress indicator shows `Card {current} of {total}` for the active deck, where total is the current session's deck size. In mastery mode (R18) it shows `{mastered} mastered · {remaining} left` instead. [caution: "Card X of Y" implies a fixed linear position, which stops being true once a card can requeue — don't reuse it for mastery mode.]
- R9 [verify: ui] When a round finishes (all cards in `order` sorted; in mastery mode, `queue` empty), a Round Complete screen shows a summary of `{known}/{total} known` and how many were marked Still Learning this round. It offers "Continue with Still Learning" (only when at least one card was marked Still Learning this round) and "Restart All". [caution: "Continue with Still Learning" drills exactly the cards marked Still Learning IN THE ROUND THAT JUST FINISHED (the round's learning set), not the whole persistent learning pile.]
- R10 [verify: ui] "Restart All" restarts a full-deck round (drill toggle reset off), preserving the current random-order setting.
- R11 [verify: ui] [caution: this "All Caught Up" state is distinct from a normal Round Complete and must not be conflated — it happens when the session's deck is empty from the START (e.g. Drill Still Learning when every card is already Know It), so there was never a round to complete.] When the session deck is empty at start, an "All Caught Up!" message is shown with no "Continue with Still Learning" option.
- R12 [verify: ui] Flashcard is entered directly when a flashcard deck is opened (loading one, or clicking its deck card on Home) — there is no Mode Select stop for flashcard decks. Entry **resumes the saved in-progress session** when one exists and is unfinished: the same card position, the same drill/random toggles (the screen's checkboxes are seeded from the engine, not from `false`). With no saved session, a finished one, or one whose `order` references ids the deck no longer has, entry falls back to a fresh full-deck session with drill off and random OFF. [caution: there is no longer any "Mode Select random state" to initialize from — do not reintroduce an external random seed/state input (the old `initialRandom` prop) to this screen.] [caution: a reload and a re-entry are deliberately the same code path — both just call `start()` on a new engine — so don't special-case one of them.]
- R13 [verify: ui] The screen's Back control exits to Home, without losing progress — the next entry resumes the session per R12. [caution: it previously returned to Mode Select — that destination is now unreachable for flashcard decks (ModeSelect spec R2), so a Back that targets it would strand the student on a screen their deck type can never legitimately show.]
- R14 [verify: unit] The session (`order`, `currentIdx`, `drillMode`, `randomOrder`, `masteryMode`, plus `queue` in mastery mode) is persisted inside the same `studydeck_flash_{title}` blob as the piles, written on every sort AND on every `start()`. [caution: persisting on `start()` is what keeps the saved session from outliving the live one — without it, a restart or toggle change would leave a stale session on disk that the next reload would resume into. The field is optional, so a pre-existing `{known, learning}` blob still parses and simply starts fresh.] [caution: `sortCard` must advance `currentIdx` BEFORE calling `persist()` — persisting first saves an index pointing at the card just sorted, and a reload re-serves it.]
- R15 [verify: unit] An explicit restart passes `forceRestart: true` and never resumes: "Restart All", any of the R6/R7/R18 toggles, and "Continue with Still Learning". [caution: R7's "toggling restarts from the top" is unchanged by resume — only an *unchanged* re-entry (reload, or Back then reopen) resumes.] [caution: every one of these call sites must pass ALL THREE options (drill, random, mastery) through from the engine, not just the one it changes — a handler that omits an option silently resets it, so flipping Random would turn mastery mode off.]
- R16 [verify: unit] The round tallies (`roundKnown`/`roundLearning`, which feed the R9 Round Complete summary) are NOT persisted — on resume they are rederived from the piles: every id before `currentIdx` in `order` counts toward whichever pile currently holds it. In mastery mode they are rederived from the queue instead: an id in `order` but no longer in `queue` was mastered this session (Know It is the only exit), and an id still queued that sits in `learning` was missed this session. [caution: without this rederivation a resumed round reports "0 / N known" at Round Complete, silently discrediting work the student did before the reload.]
- R17 [verify: ui] An "Undo" control in the sort-button row (and the Left Arrow key) undoes the LAST sort: it restores that card's exact pile membership from before the sort — which may be *neither* pile, for a card seen for the first time — drops it from the round tallies, and steps back onto it, persisting the corrected state. One step per activation, not a browsable history. It is disabled (and the key is inert) when there is nothing to undo, while a sort animation is in flight, and on the Round Complete screen. It is labeled "Undo", not "Back", because the screen header already owns a "← Back" that exits to Home (R13). [caution: undo must respect the SAME `sortingRef` debounce lock as flip/sort (R1/R2) — without it, an undo fired during the 350ms animation window pops a sort the engine hasn't applied yet, so the two silently swap and the card lands in the wrong pile.] [caution: the undo record must be captured BEFORE `sortCard` mutates the piles, or the "prior" membership it saves is the post-sort one and undo becomes a no-op.] [caution: it is NOT a second place that decides pile assignment (R5) — it only replays a membership snapshot, so the spaced-repetition seam stays intact.] [caution: the undo stack is deliberately not persisted and is cleared by every `start()`, so a reload or restart offers nothing to undo — the UI must never appear to offer an undo the engine can't honor.] [caution: in mastery mode (R18) undo must REMOVE the requeued copy a Still Learning sort left further down `queue` before unshifting the card back to the front — unshifting alone leaves the same id in the rotation twice, so the student sees the card again after they've mastered it.] [caution: the snapshot records prior ROUND-tally membership as well as prior pile membership, because a mastery-mode card can be sorted several times in one round — clearing the tallies unconditionally (correct in linear mode, where each card is sorted at most once) would erase a Still Learning mark the undone sort didn't make.]

- R18 [verify: ui] A "Study until mastered" toggle, **off by default**, switches the session from the linear `order`/`currentIdx` walk to a `queue`: Know It removes the card from the rotation permanently, Still Learning re-inserts it 3–6 positions later, and the session only reaches R9's completion screen once the queue is empty — i.e. every card in the working set has been marked Know It at least once. Its completion screen reads "Deck Mastered" and offers no "Continue with Still Learning" (there is nothing left to continue with, since a mastered card leaves the round tally's learning set). [caution: the requeue distance is deliberately 3–6 cards, not 1 — re-serving the missed card immediately turns the mode into "guess until right" rather than interleaved practice.] [caution: `order` stays the session's full working set in BOTH modes (it is what R9's `{total}` counts and what a later jump-to-card resolves against); `queue` is the mastery rotation carved out of it, not a replacement for it.] [caution: with the toggle off, behavior is byte-for-byte today's single-pass flow — R1–R11 are unaffected by this mode existing.]
- R19 [verify: ui] Right Arrow sorts Know It and Down Arrow sorts Still Learning, in both modes. [caution: they must funnel through the same sort path as the buttons, so they inherit R2's debounce lock and are inert on the Round Complete / All Caught Up screens, where no card is showing.]
